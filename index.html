Technical Reference

Cortex — Architecture & Technology Stack

Cortex · AI product knowledge platform
6 September 2026

Cortex is a governed multi-agent platform that answers customer questions about a company's products and services — grounded strictly in that company's own documentation and constraints, not general knowledge.

Think of it as an Air Traffic Control (ATC) system for the agents doing that work.

Just like ATC

  • A single planner classifies and routes every request — it never does the work itself, only decides who should
  • Governance gates run before an answer ever reaches a customer — budget checked, content checked, compliance rules applied
  • Every step is tracked in real time — per-turn latency, token spend, retrieval quality, down to a dead-letter queue for anything that scores weak
  • Nothing ships ungoverned — a document over budget, a query that hits a guardrail, or an answer that fails its quality threshold is stopped or flagged, never silently let through

Agents collaborate within strict boundaries of

🔐Security

Tenant-scoped auth, isolation enforced on every lookup, EU AI Act–aligned escalation and record-keeping

💸Cost

Two-pass budget gates — quota at upload, tokens at chunk time — plus provider fallback chosen for cost as well as uptime

📊Observability

OpenTelemetry tracing, per-step latency, full ingestion and evaluation audit trails

⚙️Reliability

Every model call falls back across providers in priority order; a failure degrades gracefully, never to silence

Memory governance

Conversation memory is bounded and policy-driven, not an unbounded transcript. Six dimensions define that policy, each backed by real, checkable code:

The same six dimensions, with the exact setting or code path behind each:

Providerconversation_memory_providerlocal | vertex_ai_session_service"local" runs short/long/episodic tiers directly against pgvector; the Vertex option delegates to Google's managed Session + Memory Bank services
Short-term windowshort_term_window_size8 turnsHow many raw recent turns are kept verbatim before they age into the summary
Summarization triggersummary_trigger_message_count12 messagesWhen older history is folded into a running summary instead of being dropped

EU AI Act aligned guardrails

Cortex has no separate "compliance module" — the obligations below are met by controls that already exist for other reasons (answer quality, tenant safety, auditability). This is an architectural alignment mapping, not a compliance certification.

ObligationCortex controlWhere it lives
Human oversight of automated decisionsEscalation triggers steer the assistant to say a human follow-up is needed (legal/tax questions, allocation/wiring requests, confidential-data requests, alleged misrepresentation); every weak-verdict answer is queued for human review regardlessagents/compliance_rules.py (ESCALATION_TRIGGERS), Dead-Letter Queue
Record-keeping / logging of system operationEvery ingestion stage and every conversation turn is logged with outcome and timing; trace spans are emitted when OpenTelemetry export is enabledDocumentEvent, QueryMetric, observability/tracing
Accuracy & robustness monitoringA golden-dataset regression suite scores faithfulness, compliance, and retrieval quality; live traffic is scored the same way by the background critic on every turnworkflows/evaluation, agents/validation/judge_agent
Risk / content controls specific to the domainA named compliance policy (no guaranteed returns, no personalized advice, no fabrication, confidentiality handling, no fee/commission discussion) is baked into the answering instruction itself, not just checked afterwardagents/compliance_rules.py (COMPLIANCE_RULES)
Data governance & traceabilityChunking strategy and its version are recorded on every Document, so a re-chunk after a strategy change is traceable rather than silently mixed into the corpusmodels/knowledge/document.py
Transparency — users should know they're talking to an AI systemNot currently surfaced: no AI-disclosure text was found in the customer portal buildfrontend/customer-portal — gap

Performance DashboardAvg / p95 latency per step, prompt/completion/total tokens, monthly token-budget consumption, hourly/daily timeseries, voice success rateStreamlit Admin Portal, page 8
Document EventsOne event per ingestion stage (extracting, cleaning, chunking, governance, embedding, persisting, indexed, or failure) with a human-readable summaryStreamlit Document Dashboard, page 4
Evaluation historyEvery golden-dataset run and every ad-hoc RAG Playground evaluation, with retrieval and judge scores, kept as a running recordStreamlit Evaluation page, page 7
Dead-Letter QueueEvery answer the critic scored as weak (faithfulness, relevancy, compliance, or refusal below threshold), with the full verdict attachedStreamlit Dead-Letter Queue, page 9

Observability is cross-cutting by design (see the dashed rail in the architecture diagram above) — it instruments layers 1–8, it is never a stage a request has to pass through to get an answer.
